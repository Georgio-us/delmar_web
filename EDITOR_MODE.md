# Редакционный режим DELMAR

В меню сайта выберите «Вход для редактора». Логин и пароль задаются только на сервере; прежний демонстрационный вход больше не действует. После входа доступны объекты, три эксклюзива и топ-3. Все изменения сохраняются в PostgreSQL и становятся доступны посетителям после загрузки страницы; уже открытые страницы обновляют каталог раз в минуту.

## Railway

1. Добавьте PostgreSQL в тот же проект Railway.
2. В Variables **сервиса сайта** добавьте `DATABASE_URL` через Add Reference Variable → PostgreSQL → DATABASE_URL. Не копируйте значение в код или чат.
3. Добавьте `EDITOR_LOGIN` и `EDITOR_PASSWORD` (12–256 символов). Пароль вводите непосредственно в Railway.
4. Примените переменные и дождитесь развёртывания ветки `main`. Dockerfile запускает Node.js 22; порт берётся из `PORT`, предоставленного Railway.
5. Откройте `/health`: `database: true` подтверждает соединение с базой, `editor: true` — настройку входа. После этого войдите через меню сайта.

`SITE_URL` необязателен: по умолчанию проверка источника запросов использует HTTPS-домен запроса. Если указываете его явно, задайте точный публичный origin сайта, без пути. Для локального HTTP используйте свой localhost origin.

Документация: [PostgreSQL в Railway](https://docs.railway.com/databases/postgresql), [переменные окружения](https://docs.railway.com/variables).

## Хранение и вход

При первом запуске сервер создаёт таблицы и один исходный снимок из 25 демонстрационных объектов. Повторный запуск и новый деплой не заменяют сохранённые записи. Снимок JSONB содержит каталог, подборки и корзину; стабильные ID связывают карточки и модалки. Обновление проверяет ревизию атомарно: устаревшая версия получает конфликт, а не перезаписывает чужую работу. При конфликте обновите страницу и повторите правку.

Сессии хранятся в базе 8 часов. Cookie в production имеет Secure, HttpOnly и SameSite=Strict. В базе хранится хеш токена сессии. Изменение пароля инвалидирует существующие сессии. Запись требует действующей сессии, проверки origin и серверной валидации данных. Ограничены попытки входа. Данные редактора не сохраняются в localStorage; старый локальный каталог автоматически не импортируется.

Без `DATABASE_URL` посетителям доступен исходный каталог, но редактор отключён. При ошибке соединения с настроенной базой сервер не подменяет её новым каталогом: запуск завершается ошибкой. Исходные серверные файлы, переменные и корзина не выдаются публичным API.

## Возможности

- Добавление, редактирование, удаление и восстановление объектов; положительные USD-цена и площадь, описание, район, застройщик, фотографии и PDF.
- Оформление эксклюзивов непосредственно в блоке; независимые редакционные тройки для каждой подборки.
- Удаление освобождает места в подборках. Восстановление возвращает прежние места, если они свободны. Корзина доступна только редактору.
- Снимок каталога, подборок и корзины сохраняется сервером; технический экспорт не показан в интерфейсе.
- До 8 JPG/PNG/WebP по 10 МБ на объект. Фотографии загружаются в R2; можно убрать отдельное фото из галереи. PDF загружается отдельной кнопкой, до 20 МБ. После загрузки сохраните объект. Также поддерживаются существующие пути `assets/` и HTTP(S)-ссылки. Старые data URL остаются совместимыми; автоматического переноса нет.
- Произвольные редакционные тексты сохраняются буквально. Для независимых RU/UA-версий позже нужны отдельные поля; текущий словарь переводит известные фразы. Интерфейс редактора русский.

## Локальный запуск и проверки

`npm ci`, затем задайте `DATABASE_URL`, `EDITOR_LOGIN`, `EDITOR_PASSWORD` и запустите `npm start`. `.env.example` описывает переменные; Node не загружает его автоматически. Реальные `.env` исключены из Git.

`npm test` проверяет HTTP-вход, cookie, права записи, общее сохранение, конфликт версий, валидацию, выход, истечение и смену пароля, ограничение попыток и запрет выдачи серверных файлов. Тестовый адаптер находится в `tests/memory-repository.cjs`; production использует только `server/repository.cjs` с PostgreSQL. Эти тесты не подменяют проверку соединения с реальной базой Railway.

`node tests/preview.cjs` — отдельный временный локальный стенд на порту 4180 с памятью вместо БД для проверки UI. Он не используется Dockerfile или production-командой.

Браузерная проверка серверного UI: вход, изменение цены и перезагрузка с сохранённой сессией проверены на локальном API-стенде; скриншот — `references/editor-mode/server-editor-desktop.png`. Соединение с production PostgreSQL проверяется отдельно через `/health`.

## Подборки и каталог

Каждая подборка (`all`, `new`, `resale`, `sea`, `family`, `center`) хранит собственный упорядоченный список до трёх ID. Редактор выбирает объекты по фотографии, коду и названию, меняет порядок и сохраняет подборку. Свободные места не заполняются автоматически. Переключение подборок меняет только рекомендованные карточки, каталог и его фильтры остаются независимыми. Заголовок показывает выбранную категорию.

Объект — одна запись каталога. Публичный код D001 соответствует внутреннему p001; эксклюзив сохраняет тот же код. На карточках отображаются код и метка «Эксклюзив», кнопки избранного убраны. Новые номера учитывают корзину и не переиспользуются при обычном удалении.

Эксклюзив добавляется из существующих объектов. «Редактировать этот эксклюзив» открывает форму непосредственно в блоке, с фотографией рядом. Можно изменить заголовок, короткое описание, обложку, три характеристики и две подписи на фото. Для каждой характеристики доступны десять SVG-иконок и источник значения: поле объекта либо собственный текст. Изменение оформления не изменяет базовую запись; значения из полей объекта обновляются вместе с ней. Количество эксклюзивов не ограничено тремя (технический лимит — 20).

Новый объект начинается с пустых текстов, цены и фотографий. Есть район, этаж, ванные, площадь террасы и метки. Без фотографий показывается SVG-заглушка. В пустом каталоге посетитель видит сообщение и возможность оставить заявку; пустые редакционные блоки скрыты, но доступны редактору для добавления. JSON-экспорт не находится в рабочем интерфейсе.

Старые данные совместимы: при загрузке прежняя тройка становится общей рекомендацией, а категории получают только подходящие объекты из этой тройки. Остальные объекты автоматически не добавляются. Существующие цены и фотографии сохраняются; миграция записывается при следующем сохранении. Демо-каталог не сбрасывается. Удаление исключает объект из подборок и эксклюзивов; восстановление возвращает его с прежним ID и размещениями, если места ещё свободны.

Проверены создание без фото, независимость каталога, выбор и порядок тройки, оформление эксклюзива в блоке, удаление и восстановление, мобильная ширина 390 px без горизонтального скролла. Скриншоты: `references/editor-mode/collections-editor-mobile.png`, `references/editor-mode/exclusive-inline-editor-desktop.png`. Автоматические тесты проверяют совместимость старых данных, пустой каталог, допустимость категорий и источников характеристик.

## Файлы в Cloudflare R2

В Variables сервиса сайта добавьте `R2_ENDPOINT`, `R2_BUCKET`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`. Endpoint: `https://<account-id>.r2.cloudflarestorage.com`; ключу нужны Object Read & Write для выбранного бакета. После применения переменных выполните деплой. Отдельный Account ID не требуется, он уже в endpoint.

Бакет остаётся приватным. Сервер принимает файлы только от вошедшего редактора и выдаёт фотографии и PDF по публичным адресам `/media/<uuid>.<extension>`. Открывать бакет или настраивать CORS не требуется. В PostgreSQL сохраняются ссылки, ключи доступа остаются на сервере. Проверяются тип, размер и сигнатура файла. SVG и HTML не принимаются.

`/health` показывает `mediaConfigured` (настройки присутствуют) и `mediaReady` (успешное чтение списка файлов R2; результат кешируется минуту). Это проверка доступа к хранилищу, а не пробная запись. Реальную запись проверяйте загрузкой через редактор.

Удаление фотографии из галереи не удаляет файл из R2: он может использоваться другим объектом или корзиной. Файл, загруженный до отмены редактирования, также остаётся в R2. Автоматическая очистка пока отсутствует. Резервная копия JSON содержит ссылки; сами файлы нужно сохранять отдельно.

Тесты загрузки проверяют авторизацию, сигнатуры, лимиты, выдачу фотографий/PDF и сохранение ссылок. Локальный UI-стенд использует `tests/memory-media.cjs`, production — `server/media.cjs`.

В браузере на локальном стенде проверены добавление фото в существующую галерею, загрузка PDF, удаление отдельного фото, сохранение и повторное открытие объекта. Загруженная фотография успешно отображается; скриншот — `references/editor-mode/r2-upload-desktop.png`.
